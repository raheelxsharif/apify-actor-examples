    GitHub Repository Language Breakdown Analyzer is an Apify Actor published by Dataspryva. It accepts 19 input fields, and mode is required. Each result can carry up to 9 declared fields, including fullName, language, languagesBreakdown, stars, forks and contributorCount. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What this actor does”, “Output per repository”, “Input”, “Use cases” and “FAQ”.

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (one repository with every enrichment). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxItems (default 20, maximum 1000) caps how many results a run collects, and so what it costs.

    What it costs

    GitHub Repository Language Breakdown Analyzer uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 19 fields of the published input schema, in the publisher's order. Required fields are marked. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    modeWhat to scrapestring requiredOne repository, a pasted list of repositories, every public repository in an organization or user account, a keyword search, or a GitHub topic.Default "orgRepos"; Example "repoDetail"; Allowed repoDetail, repoList, orgRepos, userRepos, search, topicRepos
    repoFullNameRepository (one repo)stringRepository for One repository mode. Accepts owner/repo, a full https://github.com/owner/repo URL, or the git@github.com:owner/repo.git form.Example "microsoft/vscode"
    repoFullNamesRepositories (list)arrayRepositories for A list of repositories mode. Accepts owner/repo strings and full GitHub URLs; duplicates are removed and order is preserved before sorting.Default []
    orgOrganizationstringGitHub organization login for Organization repositories mode.Default "microsoft"
    usernameUsernamestringGitHub user login for User repositories mode.
    searchQuerySearch querystringKeyword search for Keyword search mode. GitHub qualifiers work, for example stars:>1000, language:python, org:vercel, topic:llm, or pushed:>2025-01-01.Default "stars:>1000"
    topicGitHub topicstringTopic slug for Topic search mode, for example machine-learning, web-scraping, or cli.Default "machine-learning"
    languagePrimary languagestringOnly return repositories whose primary language matches this name, for example Python, TypeScript, Rust, or Jupyter Notebook. Applied as a GitHub search qualifier where possible, otherwise as a client-side filter.
    includeForksInclude forked repositoriesbooleanDiscovery modes skip forks by default. Turn this on to include forked repositories in organization, user, search, and topic results.Default false
    includeArchivedInclude archived repositoriesbooleanTurn this off to drop archived repositories from discovery results.Default true
    sortBySort results bystringSort order for discovery results. Stars and forks work through GitHub search; created, pushed, and name use the organization/user listing. Keyword-only sort options fall back to recently updated.Default "bestMatch"; Allowed bestMatch, stars, forks, updated, created, pushed, fullName
    sortOrderSort directionstringDescending (highest or newest first) or ascending.Default "desc"; Allowed desc, asc
