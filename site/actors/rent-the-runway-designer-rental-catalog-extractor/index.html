    Rent the Runway Designer Rental Catalog Extractor is an Apify Actor published by Dataspryva. It accepts 35 input fields, and mode is required. Each result can carry up to 9 declared fields, including itemName, designer, rentalPrice, retailPrice, category and rating. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Rent the Runway is a designer clothing rental service: each style has a rental price, a retail value, size availability that changes with the delivery date, and sometimes a discounted purchase option. This actor collects that catalog in structured form, including the availability context behind each price.

    It can browse a category, run a keyword search across the catalog, pull every style from one or more designers, or enrich a list of product URLs/IDs. Catalog browsing is HTTP-only and needs no account or proxy.

    Modes

    • Browse a category — 19 editor-curated categories (dresses, gowns, tops, handbags, jewelry, and more) plus the full catalog.
    • Search by keyword and filters — keyword plus any combination of occasion, color, embellishment, neckline, style, print, sleeve, season, length, maternity and wedding filters.
    • Browse designers — one or more designer names, IDs or designer URLs.
    • Specific product URLs or IDs — paste product links or style IDs (for example CULTR24).

    Use cases

    • Compare rent-versus-buy value across designers and categories.
    • Monitor rental and retail prices before wedding or event season.
    • Find what is genuinely in stock for a size and delivery date.
    • Build style round-ups with high-resolution images and product links.
    • Study fit feedback and reviewer measurements from the review data.

    Questions

    Do I need an account, cookie or proxy?

    No. The catalog, product pages and review endpoints used here are public. The actor connects directly and manages any fallback internally.

    What is the difference between the rental types?

    oneTime returns styles available for a specific rental date, duration and ZIP, with rental prices. subscription returns styles available in the membership closet; subscriptionAll also includes sold-out styles. Stock is scope-specific: a style can be sold out for subscription but available for a one-off rental.

    Why is sizesAvailable missing on some records?

    It is only emitted when availability was checked. sizesOffered still lists every size the style was made in. Availability changes by date, duration and ZIP.

    Why do some styles disappear when I change the date?

    The one-off catalog only includes styles with at least one available size for that date window. Sundays are not valid rental start dates; the actor falls back to the default date and says so in the run message.

    Can I get all reviews for an item?

    Yes. The public review endpoint is paginated in pages of 40; includeReviews follows pages until exhaustion or maxReviewsPerProduct (default 200, max 1000). The total reviewCount is always reported.

    What does the rating scale mean?

    Ratings are on Rent the Runway's 0-10 scale. ratingScale is included so the value is unambiguous.

    How do I get both 4-day and 8-day prices?

    Set includePriceTiers to true. Each selected product is read separately.

    Can I get more than 10,000 items?

    A single unfiltered search is capped at 10,000. Browse individual categories instead, or split the request by designer, occasion or other filters.

    How do I run a scheduled monitor for only new items?

    Set onlyNew to true. The actor stores seen product IDs in a persistent key-value store and skips them on later runs, so each run returns only new styles.

    Is this affiliated with Rent the Runway?

    No. This is an independent data extraction tool with no affiliation to Rent the Runway, Inc.

    Limits and notes

    What each item includes

    • Identity — productId, itemName, designer, designerId, category, categoryTree, detailUrl.
    • Prices — rentalPrice for the selected rental type/duration, retailPrice, buyPrice when the item can be bought below retail, optional rentalPrice4Day and rentalPrice8Day, plus memberRentalPrice/memberPriceDiscount when a member price is published, in USD.
    • Availability — sizesOffered (all sizes the style was made in), sizesAvailable (actually available for the chosen date/scope), availableSkuCount, availableUnits (units in rotation), availableUnitCount (subscription availability) and inStock.
    • Product detail — description, stylistNotes, fitNotes, fabricComposition, sleeve, lengthInches, occasionTags, color, embellishments, neckline, stylePersonas, maternity, seasonality, programEligibility, publishedDate.
    • Media — imageUrl (lead image) and images (all available angles, at high resolution).
    • Reviews — rating (0-10), ratingSource (catalog-list when approximate, reviews when exact), reviewCount, reviewSummary, and up to maxReviewsPerProduct recent reviews when enabled (default 200).
    • Run context — rentalType, rentalStartDate, rentalDuration, zipCode, recordType, scrapedAt.

    Every field is omitted when the source does not have it; records never contain nulls, empty strings, empty arrays or placeholder text.

    Limitations

    • Availability is a snapshot for the selected date, duration and ZIP; it changes as inventory moves.
    • One-off rental results exclude sold-out styles by design.
    • maxReviewsPerProduct bounds review text (default 200, max 1000); the total review count is always reported.
    • Care instructions, designer biographies and per-item membership rental prices are not exposed by the public payloads used here.
    • Reserve availability reports which sizes are available, not how many units back each size.
    • The default shipping ZIP is 10001 (New York); availability and delivery windows change with the ZIP.
    • Very large runs with includeDetails enabled are slower because each item needs a compact product-detail request, a reviews page for the exact rating and a member-price request. 500 detailed rows are practical; list-only runs reach 10,000.
    • onlyNew tracks the last 50,000 emitted IDs; older IDs are forgotten and may appear again.
