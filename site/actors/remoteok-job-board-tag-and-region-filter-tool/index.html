    RemoteOK Job Board Tag & Region Filter Tool is an Apify Actor published by Dataspryva. It accepts 13 input fields, and mode is required. Each result can carry up to 8 declared fields, including position, company, location, salaryMin, salaryMax and tags. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Turn RemoteOK's job board into structured data filtered the way you actually search: by keyword, by one of its 240+ skill/category tags, by region, by salary range, or by how recently a job was posted. Each listing comes back with position, company, salary, tags, location, and a direct apply link, with the description cleaned of HTML markup.

    What this actor does

    • Five modes:
      • search — free-text keyword filter over the latest feed (title, company, description, tags)
      • byTag — pull all jobs tagged with a single Remote OK tag (python, design, marketing, ...)
      • byTags — pull jobs across multiple tags and merge (jobs matching ANY of the tags)
      • byUrls — fetch jobs by direct Remote OK job page URLs
      • latest — full latest feed with no keyword/tag filter
    • Tag-based filtering — type any Remote OK tag (e.g. python, design, data-science); 240+ tags are supported
    • Region filtering — pick worldwide / americas / europe / asia / africa / oceania / usOnly from a dropdown; regions are inferred from each job's location string plus its digital nomad tag
    • Salary filtering — minSalary, maxSalary, and salaryOnly (drop jobs without a published range)
    • Recency filtering — postedSinceDays for "last N days"
    • Keyword filter — extra containsKeyword substring over title/company/description/tags
    • Optional job-page enrichment — set enrichDetails: true to add the salary range, applicant location restrictions, valid-through date, employment type, industry, benefits, and work hours from each job's page (many listings publish salary only there)
    • HTML descriptions cleaned — entities decoded, tags stripped, whitespace collapsed
    • Empty fields are omitted from every record

    Data source

    Remote OK's public JSON feed (https://remoteok.com/api, optionally ?tags=<tag>) plus each listing's public job page (https://remoteok.com/remote-jobs/<slug>). Both are cookieless and require no account, API key, or proxy.

    Use cases

    • Job aggregators — bulk-ingest fresh remote jobs into your search / matching engine
    • Recruiter intelligence — track who's hiring, in which tech stacks, with what salary ranges
    • Salary benchmarking — measure compensation ranges for specific roles or stacks
    • Market research — see which regions are publishing the most remote roles for your niche
    • Talent platforms — power "trending remote roles" or "highest-paying remote tag" dashboards
    • Personal job hunt — alert me when a Python role over $150k posts in Europe

    Questions

    What's Remote OK?

    Remote OK is one of the largest remote job boards. It aggregates fully remote tech, design, marketing, and ops jobs from companies around the world. See remoteok.com.

    Do I need login or API key?

    No. Remote OK's job listings are public, so the actor runs without any authentication.

    How many jobs does the feed return?

    About 100 latest jobs at the global level, and up to about 100 per tag (popular tags fill that cap; niche tags return fewer). Remote OK's API has no page/cursor parameter, so the way to go past ~100 is to combine several tags with byTags; the actor merges the feeds and deduplicates by job ID.

    What regions does region filtering support?

    worldwide, americas, europe, asia, africa, oceania, and usOnly. Remote OK encodes worldwide jobs via the digital nomad tag and the rest are inferred from each job's location string.

    Why is the salary range often missing?

    The public feed publishes salary for only part of the board. Many more listings carry a baseSalary on their own job page, so set enrichDetails: true to fill those (one extra HTTP request per emitted job). Set salaryOnly: true if you only want priced postings — combine it with enrichment to apply it to page salaries too.

    Can I get more than 100 jobs in a single run?

    Yes — combine byTags with multiple tags. The actor fetches each tag's feed and merges them, deduplicated by job ID. You can reach 500+ unique jobs across half a dozen tags.

    Are job descriptions formatted as HTML or plaintext?

    The actor strips HTML tags and decodes entities so the description field is clean plaintext. The original HTML is available on the job page if needed.

    What's the difference between url and applyUrl?

    url is the canonical Remote OK page; applyUrl is the company's direct apply link when distinct from the Remote OK page.

    How fresh is the data?

    Real-time — Remote OK publishes new postings as they're approved, and each run reflects whatever is live at that moment. Set postedSinceDays: 1 to capture only the most recent.

    Why does byUrls mode sometimes return fewer records than I passed in?

    Live job pages embed a JobPosting record even when the listing is no longer in the latest feed, and the actor reads it. Once Remote OK expires a listing, the page still returns HTTP 200 but drops that structured data, so expired URLs cannot be resolved. This is a source limit, not an actor error.

    Is this affiliated with Remote OK?

    No. This is an independent, third-party actor that reads Remote OK's publicly available job listings and is not affiliated with or endorsed by Remote OK.

    Limits and notes

    Limitations

    • ~100 jobs per feed slice. Remote OK serves one fixed page per tag and ignores page/offset parameters. Use byTags to union several tags; results are deduplicated by job ID.
    • Region is inferred, not a server-side filter. Remote OK's API ignores location/region parameters, so region filters on each listing's location text plus its digital nomad tag. Enable enrichDetails to also use the page's applicant-location restrictions, which fills location for more listings.
    • Expired job URLs. A job page loses its structured data after the listing expires; byUrls cannot recover it.
    • No login, cookies, or proxy needed. The actor reads the public JSON feed and public job pages with a plain HTTP client.
