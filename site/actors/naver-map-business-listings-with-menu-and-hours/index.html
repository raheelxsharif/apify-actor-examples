    Naver Map Business Listings with Menu & Hours Data is an Apify Actor published by Dataspryva. It accepts 25 input fields, and mode is required. Each result can carry up to 8 declared fields, including name, category, roadAddress, businessHoursStatus, phone and visitorReviewScore. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What this actor does”, “Output per place”, “Input”, “Use cases”, “FAQ” and “Scope / Limitations”.

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (neighborhood restaurants with full menus). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxResultsPerKeyword (default 20, maximum 5000) and maxItems (default 100, maximum 10000) cap how many results a run collects, and so what it costs.

    What it costs

    Naver Map Business Listings with Menu & Hours Data uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 25 fields of the published input schema, in the publisher's order. Required fields are marked. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    modeModestring requiredWhat to fetch. search discovers places by keyword; byUrls fetches places you already know (URLs or place IDs).Default "search"; Allowed search, byUrls
    searchKeywordsSearch keywords (mode=search)arrayKeywords to search on Naver Map, e.g. 강남 맛집 (Gangnam restaurants) or 이태원 카페 (Itaewon cafes). Include a region name for local results. Naver returns up to 100 places per keyword from the first page and up to ~300 via deeper pages; add a map area (Search coordinates + Radius) or narrower keywords for more.Default ["강남 맛집"]
    placeUrlsPlace URLs or IDs (mode=byUrls)arrayNaver Map places to fetch directly. Accepts full links (pcmap.place.naver.com, m.place.naver.com, map.naver.com/p/entry/place/...), naver.me short links, and bare numeric place IDs.Default []
    sortBySort order (mode=search)stringHow Naver orders search results. distance sorting needs Search coordinates.Default "relevance"; Allowed relevance, popular, tv, reviews, saved, distance
    searchCoordinatesSearch coordinates (mode=search)stringMap center as latitude,longitude, e.g. 37.4979,127.0276 for Gangnam Station. Used to rank results around a point, for distance sorting, and as the center of an area sweep.
    searchRadiusKmArea radius in km (mode=search)integerWhen set together with Search coordinates, the actor sweeps the whole circle (grid of map centers) instead of one center — this is how to collect more than Naver's ~300-per-keyword limit. Needs a broad keyword (e.g. 맛집).Allowed 1 to 20
    categoryCategory filterstringOnly keep places whose category contains this text (e.g. 한식, 카페, Cafe). Leave blank for all categories.
    menuKeywordMenu keyword filterstringOnly keep places whose menu names or descriptions contain this text (e.g. 피자). Requires Include place details to be on. Leave blank for all menus.
    maxResultsPerKeywordMax results per keywordintegerCap on places emitted per keyword (before filters). First page gives up to 100 places; deeper Naver pages add up to ~300 total per map center, and an area sweep multiplies that per center.Default 20; Allowed 1 to 5000
    includeDetailsInclude place detailsbooleanFetch each place's detail page for full weekly hours (breaks, last order, upcoming closures), full menus with prices, facilities, parking, photos, review breakdown and more. Slower but much richer data.Default true
    includeReviewsInclude visitor reviewsbooleanEmit real visitor reviews per place as separate recordType: "review" records (rating, text, dates, keywords, photos, owner replies). Uses Naver's cursor-paginated review API (50 per request) up to Max reviews per place; falls back to the ~20 reviews embedded on the public review page if that API is unavailable. Works in both modes.Default false
    maxReviewsPerPlaceMax reviews per placeintegerCap on review records emitted per place when Include visitor reviews is on. Naver serves 50 reviews per request and does not expose a hard cap, so this can go high (e.g. 500); each 50 reviews costs one extra request.Default 10; Allowed 1 to 3000
