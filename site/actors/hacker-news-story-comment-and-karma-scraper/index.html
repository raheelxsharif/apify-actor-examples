    Hacker News Story, Comment & Karma Scraper is an Apify Actor published by Dataspryva. It accepts 31 input fields, and mode is required. Each result can carry up to 11 declared fields, including recordType, title, company, role, url and score. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What it does”, “Services”, “How it works”, “Input”, “Output per story, job, or poll” and “Output per comment”.

    What you get

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (search with filters). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxComments (default 0, maximum 5000) and maxItems (default 50, maximum 5000) cap how many results a run collects, and so what it costs.

    What it costs

    Hacker News Story, Comment & Karma Scraper uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    All 31 fields of the published input schema, in the publisher's order. Required fields are marked. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    modeModestring requiredWhat to scrape. Feeds walk the live Hacker News lists. item looks up specific IDs, user loads profiles, search queries Hacker News history, frontPage reads a historical day, and whoIsHiring parses monthly hiring threads.Default "topStories"; Allowed topStories, newStories, bestStories, askStories, showStories, jobStories, item, user and 3 more
    itemIdsItem IDs (mode=item)arrayHacker News item IDs to look up, as numbers or numeric strings. Stories, comments, jobs, polls, and poll options are all accepted.Default []
    usernamesUsernames (mode=user)arrayHacker News usernames whose profiles and, optionally, submissions you want.Default []
    searchQueriesSearch queries (mode=search)arrayOne or more keyword queries. Every query runs independently and the results are merged without duplicates. Leave empty to browse by tags, author, or story instead.Default []
    searchSortSearch orderstringrelevance ranks by keyword match. date returns newest first and is more reproducible.Default "relevance"; Allowed relevance, date
    contentTypesSearch content typesarrayWhich Hacker News record types search should return. Selecting several types returns any of them. front_page covers only the current front page.Default ["story"]; Allowed story, comment, poll, pollopt, job, show_hn, ask_hn, front_page
    authorAuthor (mode=search)stringOnly return content written by this Hacker News username.
    storyIdStory ID (mode=search)stringOnly return content attached to this story ID. Useful with contentTypes set to comment to search inside one thread.
    exhaustiveSearchSearch past 1,000 resultsbooleanHacker News search exposes at most 1,000 hits per query. When enabled, the actor splits the requested date range into smaller windows so deeper result sets can be collected. Relevance order then follows each date window rather than one global ranking.Default false
    dateRangeFromDate range fromstringDrop items posted before this date (UTC, YYYY-MM-DD). Empty means no lower bound.
    dateRangeToDate range tostringDrop items posted after this date (UTC, YYYY-MM-DD). Empty means no upper bound.
    minScoreMinimum pointsintegerDrop stories, jobs, and polls below this point score. Comments are unaffected because Hacker News does not publish comment scores.Allowed 0 to 1000000
