    Public Record Contact Finder: Mobile Numbers & Personal Emails

    Resolve a person from a name, email, social profile or lead dataset, then collect public mobile numbers and personal or work emails. Each contact carries its source, match evidence and confidence score; suppression is always honoured.

    Public Record Contact Finder: Mobile Numbers & Personal Emails is an Apify Actor published by Dataspryva. It accepts 19 input fields, and mode is required. Each result can carry up to 11 declared fields, including inputRef, resolvedName, title, headline, employer and location. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “Input modes”, “Options”, “Input reference”, “What each row contains”, “Where the data comes from” and “How confidence works”.

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (example input). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxItems (default 20, maximum 100) caps how many results a run collects, and so what it costs.

    What it costs

    Public Record Contact Finder: Mobile Numbers & Personal Emails uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 19 fields of the published input schema, in the publisher's order. Required fields are marked. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    modeInput modestring requiredHow the people in this run are identified. Pick the mode that matches the field you fill in.Default "person"; Allowed person, email, linkedinProfile, facebookProfile, socialHandle, leads
    peoplePeoplearrayOne row per person. Full name is required; city and state or a company domain help disambiguate common names. Optional profile URLs and social handles enrich the identity graph.Default []; Example [{"fullName": "John Marvin Smith", "city": "San Antonio",...
    emailsEmail addressesarrayWork or personal email addresses. Each address is matched to a public Gravatar profile and public commit history, then to public records when a name is resolved.Default []; Example ["torvalds@linux-foundation.org"]
    linkedinProfilesLinkedIn profile URLsarrayPublic LinkedIn profile URLs. The actor reads the public profile page without a login.Default []; Example ["https://www.linkedin.com/in/williamhgates"]
    facebookProfilesFacebook profile URLsarrayPublic Facebook profile URLs. Only information visible without a login is used.Default []; Example ["https://www.facebook.com/zuck"]
    socialHandlesSocial handlesarrayA known handle per person. Handles are resolved directly, not guessed.Default []; Example [{"platform": "github", "handle": "sindresorhus"}]
    leadsLead rowsarrayRows copied from another actor or a CSV. Columns are mapped automatically by common names such as name, email, company, website, city, state, linkedinUrl, facebookUrl, githubUsername and xHandle.Default []
    leadsDatasetIdLead dataset IDstringOptional Apify dataset ID to read lead rows from. It is combined with the rows above.Default ""
    leadsFieldMappingLead column mappingobjectOptional override when a dataset uses different column names. Example: {"fullName": "contact_name", "email": "work_email"}.Default {}
    contactTypesWanted contact typesarrayOnly these contact types are returned. anyPhone includes mobiles, landlines, VoIP and toll-free numbers.Default ["mobile", "anyPhone", "personalEmail", "workEmail"]; Allowed mobile, anyPhone, personalEmail, workEmail
    countriesCountriesarrayISO country codes to search. US public-record people search and the NPI registry run for US people; other countries use profile, website and registry data.Default ["US"]
    minMatchConfidenceMinimum match confidenceintegerContacts below this score (0-100) are dropped. Higher values reduce wrong-person matches.Default 40; Allowed 0 to 100
