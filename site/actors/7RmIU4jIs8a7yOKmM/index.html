Hcareers Hotel & Restaurant Job Finder by Category

Hcareers is the dedicated job board for hotels, resorts, restaurants, casinos and the wider hospitality industry. This actor searches it by keyword, city, state/province, any of its 26 job categories or 49 hotel brands, walks the site's entire jobs index, fetches specific job postings, and scrapes employer profiles — returning pay ranges, perks, apply links, photos, full descriptions and property details. No login, proxy, or cookies required.

What this actor does

  • Four modes: search (keyword / location / state / category / brand browsing), allJobs (the complete open-jobs index, with an optional updatedSince date for incremental runs), byUrls (specific job postings), and employers (company profiles, with their open jobs)
  • Complete filter surface: 26 hospitality job categories, 49 live state/province pages (US + Canada), 49 hotel-brand pages, free-text city search, remote-only, and employment-type filtering
  • Rich job records: advertised pay with parsed salaryMin/salaryMax/salaryPeriod, perks, the application link (employer ATS when available), photo galleries, and the employer's property profile
  • Employer data: company description, address, property type, property/job counts, parent brand details and sister properties
  • Empty fields are omitted — a field the listing genuinely lacks is left out, never sent as null

Output per job

  • jobId, jobUrl, title
  • employer, employerLogoUrl, employerProfileUrl
  • brand, brandLogoUrl, brandProfileUrl — parent hotel group, when the property is managed by one
  • location, locationRaw, locationCity, locationState, locationPostalCode, locationCountry
  • category — set when a category filter was used
  • employmentType, employmentTypeBadges[], isRemote
  • compensationRaw — pay exactly as advertised; salaryMin, salaryMax, salaryCurrency, salaryPeriod — parsed from the advertised text (HOUR, YEAR, MONTH, …) only when the listing states it; compensationAmount — structured amount when the site provides one
  • perks — advertised perks (e.g. signing bonus)
  • applyUrl — the job's application link (employer's ATS, or Hcareers' own application flow)
  • description (plain text), descriptionHtml, photoUrl, photoUrls[]
  • industry, datePosted, closingDate — ISO 8601, postedRelative (e.g. "6 days ago")
  • employerAbout, employerAddress, employerPropertyType, employerPropertyCount, employerJobCount, brandAbout
  • recordType: "job", scrapedAt

Output per employer (mode = employers)

  • employerName, employerProfileUrl
  • about, address, propertyType, propertyCount, jobCount
  • brandName, brandProfileUrl, brandAbout
  • properties[] — sister properties with name, location, jobCount, url
  • recordType: "employer", scrapedAt

Use cases

  • Hospitality recruitment intelligence — track hiring activity by brand, state, category and property
  • Compensation benchmarking — aggregate advertised pay ranges by role, category, brand or region
  • Job feeds for career sites — refresh a hospitality job board with structured records and working apply links
  • Employer/competitor research — follow which properties a management group is staffing and where
  • Labor-market datasets — incremental exports of the whole board for analysis and dashboards

FAQ

Does this require an Hcareers account? No — every listing, company profile and job detail page used is public.

What's the difference between search and allJobs? search supports filters and returns what matches; allJobs walks Hcareers' complete jobs index, so it is the way to export every open posting (with updatedSince for incremental refresh — a date or an exact timestamp). Hcareers does not print a job category on posting pages, so allJobs records carry no category; use search with a category filter when you need that field.

Why is pay missing on some jobs? Many hospitality employers don't advertise pay at all. When they do, compensationRaw carries the exact text and salaryMin/salaryMax/salaryPeriod are parsed from it; if the text can't be parsed faithfully, only the raw text is returned. Pay mentioned only informally somewhere inside the free-text description (often ambiguous — a price or discount, not a wage) is deliberately not guessed into the structured fields.

Why does applyUrl sometimes point back to hcareers.com? Some employers accept applications through Hcareers' own application flow (which asks applicants for a free account); others link straight to their ATS. The actor returns whichever the posting uses.

Why do some jobs show a brand and others don't? Independent properties have no parent group. When a hotel is managed by a brand or management company, Hcareers surfaces it as "A property of: …" and the actor includes it.

What is the property profile? Each job's detail page includes the employer's company description, address, property type, and property and job counts; the actor copies these to employer* fields. Mode employers returns the same data as its own record, with sister properties.

Can I combine category, state, brand and keywords? Yes — filters combine with AND logic in search mode.

Is this affiliated with Hcareers? No, this is a third-party actor using only publicly visible pages.

How fresh is the data? Every run reads live pages, so listings reflect the site at run time; new postings appear on the same day they're added.
