Use Hacker News Story, Comment & Karma Scraper with Python

Pull Hacker News front-page, newest, best, Ask HN, Show HN, or job stories, look up specific items or user profiles, or run a full-text search across HN history. Filter by score, domain, date range, and comment count or author.

1. Choose the data you need

Review the published README for supported collection modes, examples, and limits. The recipe below uses the current published input definition.

FieldTypeRequiredDescription
modestringrequiredWhat to scrape. Feeds walk the live Hacker News lists. `item` looks up specific IDs, `user` loads profiles, `search` queries Hacker News history, `frontPage` reads a historical day, and `whoIsHiring` parses monthly hiring threads.
itemIdsarrayoptionalHacker News item IDs to look up, as numbers or numeric strings. Stories, comments, jobs, polls, and poll options are all accepted.
usernamesarrayoptionalHacker News usernames whose profiles and, optionally, submissions you want.
searchQueriesarrayoptionalOne or more keyword queries. Every query runs independently and the results are merged without duplicates. Leave empty to browse by tags, author, or story instead.
searchSortstringoptional`relevance` ranks by keyword match. `date` returns newest first and is more reproducible.
contentTypesarrayoptionalWhich Hacker News record types search should return. Selecting several types returns any of them. `front_page` covers only the current front page.
authorstringoptionalOnly return content written by this Hacker News username.
storyIdstringoptionalOnly return content attached to this story ID. Useful with `contentTypes` set to `comment` to search inside one thread.
exhaustiveSearchbooleanoptionalHacker News search exposes at most 1,000 hits per query. When enabled, the actor splits the requested date range into smaller windows so deeper result sets can be collected. Relevance order then follows each date window rather than one global ranking.
dateRangeFromstringoptionalDrop items posted before this date (UTC, `YYYY-MM-DD`). Empty means no lower bound.
dateRangeTostringoptionalDrop items posted after this date (UTC, `YYYY-MM-DD`). Empty means no upper bound.
minScoreintegeroptionalDrop stories, jobs, and polls below this point score. Comments are unaffected because Hacker News does not publish comment scores.
minCommentCountintegeroptionalDrop stories and polls with fewer than this many comments.
domainAllowlistarrayoptionalKeep only stories whose link host contains one of these text fragments. For example, `github.com` or `arxiv.org`.
domainBlocklistarrayoptionalDrop stories whose link host contains one of these text fragments. For example, `twitter.com` or `x.com`.
excludeDeadOrDeletedbooleanoptionalDrop items marked dead or deleted by Hacker News. Turning this off uses the slower exact comment path so those records can be included.
commentAuthorFilterarrayoptionalOnly keep comments written by these usernames. Matching is case-insensitive and accepts partial names.
commentSortstringoptional`rank` keeps Hacker News display order. `newest` orders sibling replies newest first.
maxCommentsintegeroptionalHow many comments to collect for each story. 0 skips comment collection. This is applied after a story passes your filters.
maxDepthintegeroptionalDeepest reply level to keep when comments are collected. Root comments are depth 0.
enableCommentHierarchybooleanoptionalWhen true, each story carries a nested `comments` tree. When false, comments are separate rows and never contain duplicate reply rows.
includeSubmissionsbooleanoptionalFor mode `user`, also emit the user's recent stories and comments as normal records after the profile.
submissionTypesstringoptionalWhich submissions to emit when `includeSubmissions` is enabled.
frontPageDatestringoptionalHistorical day to read in mode `frontPage`, as `YYYY-MM-DD`. Empty uses yesterday (UTC).
hiringMonthsintegeroptionalHow many recent monthly Who is hiring? threads to parse. Ignored when specific thread IDs are supplied.
hiringThreadIdsarrayoptionalSpecific Who is hiring? thread IDs to parse. Overrides the automatic monthly selection.
hiringKeywordsarrayoptionalKeep only job posts whose text, company, role, location, or tech stack contains one of these terms.
remoteOnlybooleanoptionalKeep only hiring posts that explicitly mention remote work.
maxItemsintegeroptionalHard cap on emitted records across all types. Nested comments also count toward this cap.
includeAuthorProfilesbooleanoptionalAdd `authorKarma` and `authorCreatedAt` to stories and comments. This costs one extra lookup per unique author.
startUrlsarrayoptionalHacker News links to read directly: item, user, historical front-page, and hiring-thread URLs. IDs and URLs are merged with the mode-specific lists.

3. Start an Actor run

Set APIFY_TOKEN in your environment. Python 3.10 or newer is sufficient; this recipe uses no third-party packages.

Execution may incur charges. Review current pricing on Apify. The request asks for a 120-second timeout and a charge limit; these settings are subject to Apify’s pricing and do not guarantee an all-inclusive spending cap.

import json
import os
import urllib.request

# Save the schema-derived example as input.json; review and edit it first.
with open("input.json", encoding="utf-8") as stream:
    actor_input = json.load(stream)

token = os.environ["APIFY_TOKEN"]
request = urllib.request.Request(
    "https://api.apify.com/v2/acts/shC9wAKWFYbt1zZYs/runs?timeout=120&maxTotalChargeUsd=0.50",
    data=json.dumps(actor_input).encode("utf-8"),
    headers={"Authorization": "Bearer " + token, "Content-Type": "application/json"},
    method="POST",
)
# This starts a potentially billable run. Do not automatically retry this POST.
with urllib.request.urlopen(request, timeout=40) as response:
    run = json.load(response)["data"]
print("Run ID:", run["id"])
print("Status:", run["status"])
