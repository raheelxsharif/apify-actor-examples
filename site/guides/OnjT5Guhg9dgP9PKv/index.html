Use Snapchat Snap Map Place & Live Snap Extractor with Python

Search Snapchat's Snap Map by place name or landmark and get each place's coordinates, category, favorite and snap counts, plus the media link for its most recent public snap.

1. Choose the data you need

Review the published README for supported collection modes, examples, and limits. The recipe below uses the current published input definition.

FieldTypeRequiredDescription
modestringoptionalChoose what to scrape: search Snap Map places by keyword, look up specific place URLs or IDs, or browse US cities and categories.
keywordsarrayoptionalPlace names, landmarks, venues or addresses to search on Snap Map. Used in Search places mode. Examples: Times Square, Eiffel Tower, Tokyo Station.
placeUrlsarrayoptionalSnapchat place page URLs, /place/ paths, or bare place UUIDs. Used in Get details mode. Example: https://www.snapchat.com/place/times-square/c8b4f0ee-9992-11e8-88c9-673ed985ff70.
cityUrlsarrayoptionalUS city names, Snapchat local URLs, or local paths for Browse mode. Examples: new-york, chicago, https://www.snapchat.com/local/united-states/california/los-angeles.
categoriesarrayoptionalOptional category slugs for Browse mode, such as bars, restaurants, coffee-shops, historic-landmarks or parks. Leave empty to use the city hub's six featured categories.
resultTypesarrayoptionalWhich Explore result groups to return in Search places mode. Places is the Snap Map place search; the other groups are the public entities Snapchat shows for the same keyword.
outputTypestringoptionalPlace records keep one row per place with live snaps nested. Live snap records flatten every live snap into its own row with the place's coordinates, which is easier for maps and time-series analysis.
maxResultsPerKeywordintegeroptionalMaximum rows to keep for each result type per keyword. Snapchat returns up to 10 places and roughly 20-24 items for the other groups.
maxPlacesintegeroptionalMaximum places to process in Get details mode.
maxPlacesPerCityintegeroptionalMaximum places to keep per city in Browse mode after merging the hub categories.
maxSnapsPerPlaceintegeroptionalMaximum live snaps to keep per place. Snapchat's public page exposes a sample of 2-36 current snaps per place.
includeSnapDatabooleanoptionalAdd the public snap sample for each place with media URL, thumbnail, creator and timestamp. Snapchat mixes recent map posts with older Spotlight shares, so use the age filter below to keep only fresh posts. Also fills the legacy first-snap fields.
includePlaceDetailsbooleanoptionalOpen each place page to fill coordinates, address, phone, website, category, rating, reviews, opening hours, popularity and nearby places. Turn off for a faster search-card-only run. Nearby places, reviews, favorite sorting, live-snap output and the live-snap filter open place pages automatically because those values only exist there.
includeNearbyPlacesbooleanoptionalAdd the places Snapchat lists at the same location, with their coordinates and categories.
includeReviewsbooleanoptionalAdd up to 20 public place reviews with rating, text, date and source URL.
includePopularityHoursbooleanoptionalAdd Snapchat's 168 hourly popularity values per place (7 days x 24 hours) plus the peak hour and day index. This is the per-place heatmap signal.
minRatingnumberoptionalKeep only places whose public rating is at least this value. Places without a rating are dropped when this is above 0.
requireLiveSnapsbooleanoptionalDrop places that currently have no public live snaps.
snapMaxAgeHoursintegeroptionalKeep only snaps posted within this many hours. Set 0 to keep every snap the public page returns. liveSnapCount and latestSnapAt describe only the kept snaps, and the live-snap filter uses that kept count.
sortBystringoptionalOrder places by Snapchat's source order, rating, favorite count or number of live snaps.
proxyConfigurationobjectoptionalOptional. The public Snapchat pages used here work without a proxy.

3. Start an Actor run

Set APIFY_TOKEN in your environment. Python 3.10 or newer is sufficient; this recipe uses no third-party packages.

Execution may incur charges. Review current pricing on Apify. The request asks for a 120-second timeout and a charge limit; these settings are subject to Apify’s pricing and do not guarantee an all-inclusive spending cap.

import json
import os
import urllib.request

# Save the schema-derived example as input.json; review and edit it first.
with open("input.json", encoding="utf-8") as stream:
    actor_input = json.load(stream)

token = os.environ["APIFY_TOKEN"]
request = urllib.request.Request(
    "https://api.apify.com/v2/acts/OnjT5Guhg9dgP9PKv/runs?timeout=120&maxTotalChargeUsd=0.50",
    data=json.dumps(actor_input).encode("utf-8"),
    headers={"Authorization": "Bearer " + token, "Content-Type": "application/json"},
    method="POST",
)
# This starts a potentially billable run. Do not automatically retry this POST.
with urllib.request.urlopen(request, timeout=40) as response:
    run = json.load(response)["data"]
print("Run ID:", run["id"])
print("Status:", run["status"])

Questions before you run

Which inputs are required?

No top-level fields are marked required in the published schema. Conditional requirements can still apply; check the README.

What does this guide verify?

The fields, prefills, and schema links are rendered from the published build. This is a usage recipe, not a paid live extraction test. Source availability and collection results can vary.

What if the run request times out?

Check Apify Console before retrying. The first request may already have created a run. Do not automatically repeat a run-creation POST.
