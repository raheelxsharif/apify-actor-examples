Use Naver Map Business Listings with Menu & Hours Data with Python

Search Naver Map by keyword or place URL and get address, phone, weekly hours, menu with prices, amenities, transit access, booking links, and review scores for each business.

1. Choose the data you need

Review the published README for supported collection modes, examples, and limits. The recipe below uses the current published input definition.

FieldTypeRequiredDescription
modestringrequiredWhat to fetch. `search` discovers places by keyword; `byUrls` fetches places you already know (URLs or place IDs).
searchKeywordsarrayoptionalKeywords to search on Naver Map, e.g. `강남 맛집` (Gangnam restaurants) or `이태원 카페` (Itaewon cafes). Include a region name for local results. Naver returns up to 100 places per keyword from the first page and up to ~300 via deeper pages; add a map area (Search coordinates + Radius) or narrower keywords for more.
placeUrlsarrayoptionalNaver Map places to fetch directly. Accepts full links (pcmap.place.naver.com, m.place.naver.com, map.naver.com/p/entry/place/...), `naver.me` short links, and bare numeric place IDs.
sortBystringoptionalHow Naver orders search results. `distance` sorting needs Search coordinates.
searchCoordinatesstringoptionalMap center as `latitude,longitude`, e.g. `37.4979,127.0276` for Gangnam Station. Used to rank results around a point, for distance sorting, and as the center of an area sweep.
searchRadiusKmintegeroptionalWhen set together with Search coordinates, the actor sweeps the whole circle (grid of map centers) instead of one center — this is how to collect more than Naver's ~300-per-keyword limit. Needs a broad keyword (e.g. `맛집`).
categorystringoptionalOnly keep places whose category contains this text (e.g. `한식`, `카페`, `Cafe`). Leave blank for all categories.
menuKeywordstringoptionalOnly keep places whose menu names or descriptions contain this text (e.g. `피자`). Requires Include place details to be on. Leave blank for all menus.
maxResultsPerKeywordintegeroptionalCap on places emitted per keyword (before filters). First page gives up to 100 places; deeper Naver pages add up to ~300 total per map center, and an area sweep multiplies that per center.
includeDetailsbooleanoptionalFetch each place's detail page for full weekly hours (breaks, last order, upcoming closures), full menus with prices, facilities, parking, photos, review breakdown and more. Slower but much richer data.
includeReviewsbooleanoptionalEmit real visitor reviews per place as separate `recordType: "review"` records (rating, text, dates, keywords, photos, owner replies). Uses Naver's cursor-paginated review API (50 per request) up to Max reviews per place; falls back to the ~20 reviews embedded on the public review page if that API is unavailable. Works in both modes.
maxReviewsPerPlaceintegeroptionalCap on review records emitted per place when Include visitor reviews is on. Naver serves 50 reviews per request and does not expose a hard cap, so this can go high (e.g. 500); each 50 reviews costs one extra request.
minVisitorReviewScorenumberoptionalOnly keep places with a visitor review score at or above this value (0-5). Leave blank for no filter.
minVisitorReviewCountintegeroptionalOnly keep places with at least this many visitor reviews. Leave blank for no filter.
openNowbooleanoptionalOnly keep places currently marked as open by Naver Map.
hasBookingbooleanoptionalOnly keep places that support online booking/reservations through Naver.
hasNpaybooleanoptionalOnly keep places that accept Naver Pay.
hasCouponbooleanoptionalOnly keep places with an active coupon or promotion.
takeoutbooleanoptionalOnly keep places marked as offering takeout (포장).
newlyOpenedbooleanoptionalOnly keep places Naver marks as newly opened.
wheelchairAccessiblebooleanoptionalOnly keep places with a wheelchair-accessible entrance.
maxItemsintegeroptionalHard cap on total emitted place records across all keywords/URLs (review records are extra).
monitoringModebooleanoptionalRecurring-job mode: remembers each place between runs (in the Actor's key-value store) and emits only places that are new or whose name, category, address, phone, homepage, weekly hours, menus, or amenities changed. Adds `changeType` (NEW/UPDATED/UNCHANGED) and `changedFields` to each emitted place. Review counts and current open/closed status are ignored so runs are not billed for noise.
monitoringStateKeystringoptionalOptional name for the monitoring state (mode=monitoringMode). Leave blank to derive the key from the run inputs, so the same keywords/URLs always compare against the same memory.
emitUnchangedbooleanoptionalIn Monitoring mode, also emit places with `changeType: "UNCHANGED"` instead of skipping them.

3. Start an Actor run

Set APIFY_TOKEN in your environment. Python 3.10 or newer is sufficient; this recipe uses no third-party packages.

Execution may incur charges. Review current pricing on Apify. The request asks for a 120-second timeout and a charge limit; these settings are subject to Apify’s pricing and do not guarantee an all-inclusive spending cap.

import json
import os
import urllib.request

# Save the schema-derived example as input.json; review and edit it first.
with open("input.json", encoding="utf-8") as stream:
    actor_input = json.load(stream)

token = os.environ["APIFY_TOKEN"]
request = urllib.request.Request(
    "https://api.apify.com/v2/acts/l8lB2zLDoXJ2xjpAe/runs?timeout=120&maxTotalChargeUsd=0.50",
    data=json.dumps(actor_input).encode("utf-8"),
    headers={"Authorization": "Bearer " + token, "Content-Type": "application/json"},
    method="POST",
)
# This starts a potentially billable run. Do not automatically retry this POST.
with urllib.request.urlopen(request, timeout=40) as response:
    run = json.load(response)["data"]
print("Run ID:", run["id"])
print("Status:", run["status"])
