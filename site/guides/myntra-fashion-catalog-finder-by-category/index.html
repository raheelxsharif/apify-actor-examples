Use Myntra Fashion Catalog Finder by Category & Brand with Python

Search Myntra's fashion catalog by keyword, category, or brand, or fetch specific products, for MRP, price, discount, ratings, sizes, colors, and category detail.

1. Choose the data you need

Review the published README for supported collection modes, examples, and limits. The recipe below uses the current published input definition.

FieldTypeRequiredDescription
modestringoptionalWhat to fetch. Each mode has its own input list below.
searchQueriesarrayoptionalOne or more keyword searches (mode=search), e.g. `tshirts`, `printed kurtas`, `nike running shoes`. Each query is fetched separately and duplicates are removed.
categoriesarrayoptionalOne or more category listings (mode=browseByCategory).
brandsarrayoptionalOne or more brands to browse (mode=browseByBrand), e.g. `nike`, `levis`, `tommy hilfiger`. Spaces and punctuation are normalized automatically.
startUrlsarrayoptionalMyntra listing, search, category, brand, or product URLs (mode=byUrl). Product URLs are fetched as products; everything else is fetched as a listing.
productIdsarrayoptionalNumeric Myntra product IDs or product URLs (mode=byProductIds), e.g. `36674095`.
genderstringoptionalRestrict listing results to one gender segment. Applied on Myntra's side.
sortBystringoptionalHow Myntra orders listing results.
minPriceintegeroptionalOnly products whose selling price is at least this amount. 0 means no minimum.
maxPriceintegeroptionalOnly products whose selling price is at most this amount. 0 means no maximum.
minDiscountintegeroptionalOnly products discounted by at least this percentage. 0 means no minimum.
minRatingnumberoptionalOnly products rated at least this value (0-5). Products without a rating are excluded when this is above 0.
containsKeywordstringoptionalOnly products whose name contains this keyword (case-insensitive). Leave empty for all products.
includeDetailsbooleanoptionalOpen each product page to add sellers, addresses, per-size stock and measurements, specifications, rating breakdown, policies, videos, and tags. Slower but much richer. URL and product-ID modes always fetch details.
includeReviewsbooleanoptionalEmit one row per written review with recordType `review`, in addition to product rows.
maxReviewsPerProductintegeroptionalReview rows to fetch for each product when written reviews are enabled (1-2000).
maxItemsintegeroptionalTotal product rows to save across all queries, categories, brands, and URLs (1-10000). Review rows are additional.
splitLargeSearchesbooleanoptionalGo past the per-filter result cap by fetching gender, price-band, and sort slices, then removing duplicates. Recommended for deep exports.
proxyConfigurationobjectoptionalOptional override. Leave untouched and the actor selects a working connection automatically.

3. Start an Actor run

Set APIFY_TOKEN in your environment. Python 3.10 or newer is sufficient; this recipe uses no third-party packages.

Execution may incur charges. Review current pricing on Apify. The request asks for a 120-second timeout and a charge limit; these settings are subject to Apify’s pricing and do not guarantee an all-inclusive spending cap.

import json
import os
import urllib.request

# Save the schema-derived example as input.json; review and edit it first.
with open("input.json", encoding="utf-8") as stream:
    actor_input = json.load(stream)

token = os.environ["APIFY_TOKEN"]
request = urllib.request.Request(
    "https://api.apify.com/v2/acts/VF1ZCnsosUQJo2e7b/runs?timeout=120&maxTotalChargeUsd=0.50",
    data=json.dumps(actor_input).encode("utf-8"),
    headers={"Authorization": "Bearer " + token, "Content-Type": "application/json"},
    method="POST",
)
# This starts a potentially billable run. Do not automatically retry this POST.
with urllib.request.urlopen(request, timeout=40) as response:
    run = json.load(response)["data"]
print("Run ID:", run["id"])
print("Status:", run["status"])

Questions before you run

Which inputs are required?

No top-level fields are marked required in the published schema. Conditional requirements can still apply; check the README.

What does this guide verify?

The fields, prefills, and schema links are rendered from the published build. This is a usage recipe, not a paid live extraction test. Source availability and collection results can vary.

What if the run request times out?

Check Apify Console before retrying. The first request may already have created a run. Do not automatically repeat a run-creation POST.
